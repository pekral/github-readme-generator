## Podstatné zjištění — proto ten „Status" odstavec

`composer.json` balíček popisuje jako *„Records model changes to an audit trail"*, ale **žádný kód tuto funkci neimplementuje**. Grep přes `src/`, `config/` i `database/` nenašel jediný trait, observer, event listener ani čtení konfigurace — `enabled` a `retention_days` nikde nikdo nečte. Jediná třída v `src/` je service provider, který publikuje config a načítá migrace.

Napsat běžnou sekci *Usage* s `use Auditable;` na modelu by znamenalo vymyslet si API, které neexistuje. Místo toho README explicitně uvádí, co balíček dnes doopravdy dodává. Pokud ta vrstva existuje jinde (jiná větev, nezveřejněný commit), řekněte mi to a Usage doplním z reálného kódu.

## Co jsem záměrně vynechal

- **Sekci Testing.** `composer.json:23` deklaruje `"test": "vendor/bin/pest"`, ale Pest **není** v `require-dev` a v repozitáři nejsou žádné testy — příkaz by selhal. Nechtěl jsem publikovat nefunkční příkaz. Doporučuji buď doplnit `pestphp/pest` do `require-dev`, nebo skript odstranit.
- **Badges.** Není CI workflow ani ověřitelný záznam na Packagistu.
- **Odkazy na repozitář / issues.** `composer.json` nemá `homepage` ani `support`; git metadata v tomto adresáři patří nadřazenému repozitáři, ne balíčku.
